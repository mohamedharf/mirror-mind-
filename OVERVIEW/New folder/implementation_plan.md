# تقرير تحليل مشاكل إدخال البيانات والأحداث المفتوحة

بناءً على طلبك، قمت بتحليل المشاكل الثلاثة بعمق. هذا التقرير يوضح المشكلة، أسبابها، وأفضل الطرق البرمجية لإصلاحها، دون إجراء أي تعديل فعلي على الكود حتى تعطي موافقتك.

---

## 1. مشكلة الكميات الضمنية (Implicit Quantities)
**وصف المشكلة:** المستخدم يكتب "بشرب فنجان قهوة"، والنظام يتجاهلها لأن الـ Prompt يوجه الذكاء الاصطناعي لتجاهل الكميات غير الصريحة (الرقمية).
**التحليل:** القرار السابق في الـ Prompt كان يهدف لتقليل الهلوسة، لكنه كان صارماً جداً وتجاهل الطبيعة اللغوية البشرية (حيث المفرد = 1).
**الحل الأفضل:** 
تعديل سطر واحد في `EXTRACTION_USER` داخل `apps/entries/ai.py`.
- **الحالي:** `لو الكمية غير واضحة في النص → لا تُضفها`
- **المقترح:** `لو ذُكر العنصر أو الوحدة بصيغة المفرد (مثل "فنجان"، "سيجارة") دون رقم صريح، افترض أن القيمة = 1. تجاهل الإضافة فقط إذا كانت الجملة عامة جداً (مثل "أنا بحب القهوة").`

---

## 2. مشكلة الأحداث الممتدة (النوم، العمل) وحساب المدة
**وصف المشكلة:** النوم والعمل أحداث لها مدة زمنية (Duration) وليست لحظية كشرب القهوة. النظام يمتلك حقل `is_open_event=True` لكنه لا يُستغل لحساب المدة تلقائياً عند إغلاق الحدث.

**التحليل العميق للحلول:**
الهدف هو الوصول لـ Zero Friction. عندما يقول المستخدم "صحيت"، يجب أن يُغلق حدث "هنام" السابق وتُحسب المدة تلقائياً.

### الخيار (أ): الاعتماد الكامل على الـ LLM (LLM Matching)
- **الآلية:** نرسل للـ LLM قائمة بالأحداث المفتوحة الحالية، ونسأله: "هل هذا النص يغلق أياً من هذه الأحداث؟".
- **العيوب:** أبطأ، يستهلك Tokens أكثر، وعرضة للهلوسة (قد يربط حدث عمل بنوم بالخطأ).

### الخيار (ب): الاعتماد على الكلمات المفتاحية (Keyword Detection) + UI Prompt [الخيار الموصى به]
- **الآلية:** 
  1. الواجهة الأمامية أو الخلفية تمتلك قائمة بالكلمات المفتاحية للإغلاق (صحيت، قمت، خلصت، وقفت، رجعت).
  2. إذا كان لدى المستخدم حدث مفتوح (مثلاً "نوم")، وكتب "صحيت"، يكتشف النظام الكلمة المفتاحية.
  3. تُظهر الواجهة للمستخدم رسالة بسيطة (Toast أو Card): "هل تريد إنهاء حدث (نوم) الساري؟ [نعم/لا]".
  4. عند الضغط على "نعم"، يتم ربط الإدخال الجديد بالقديم باستخدام حقل `parent_id` الموجود مسبقاً في قاعدة البيانات.
- **المميزات:** سريع جداً، لا يستهلك ذكاء اصطناعي إضافي، دقيق بنسبة 100% لأن المستخدم يؤكد الإغلاق، ومريح (Frictionless).

**كيفية تنفيذ الخيار (ب) برمجياً:**
1. **الواجهة الخلفية (Backend):**
   - إضافة دالة في `apps/entries/views.py` (مثلاً `active_open_events`) ترجع الأحداث المفتوحة التي ليس لها أبناء (`children`).
   - عند إضافة `parent_id` لـ Entry (إغلاق الحدث)، نقوم بحساب الفرق الزمني:
     `duration_hours = (child_entry.created_at - parent_entry.created_at).total_seconds() / 3600`
   - إنشاء `Metric` تلقائياً (مثلاً "نوم"، بقيمة `duration_hours`، وحدة "ساعة") وربطه بالحدث الأب أو الابن.
2. **الواجهة الأمامية (Frontend):**
   - استدعاء `active_open_events` والاحتفاظ بها في الـ State.
   - عند كتابة المستخدم لنص جديد، نفحص النص محلياً: `['صحيت', 'قمت'].some(word => text.includes(word))` وإذا تطابق مع حدث "نوم" مفتوح، نقترح الإغلاق.
   - يمكن أيضاً عرض الأحداث المفتوحة بشكل مرئي في أعلى الشاشة كـ "مؤقتات نشطة" (Active Timers) يمكن للمستخدم إيقافها بضغطة زر دون كتابة أي شيء.

## 3. نقص البيانات الأولية (Seed Data)
**وصف المشكلة:** المقياس "عمل" غير موجود في قاعدة البيانات الافتراضية.
**التحليل:** يجب أن يكون النظام جاهزاً للتعرف على الأحداث الشائعة منذ اليوم الأول.
**الحل الأفضل:**
- تعديل ملف `apps/entries/management/commands/seed_metrics.py`.
- إضافة الـ Metric التالي للقائمة:
  ```python
  {
      "name": "عمل",
      "unit": "ساعة",
      "category": "productivity",
      "aliases": ["شغل", "تاسك", "مذاكرة", "عملت"]
  }
  ```

## 💡 التوصية وخطة العمل المقترحة
1. **Prompt Update:** تعديل `ai.py` فوراً لحل مشكلة القيمة = 1.
2. **Seed Data:** تحديث `seed_metrics.py` وإضافة "عمل".
3. **Open Events Logic:** 
   - إنشاء نقطة نهاية (Endpoint) للمهام المفتوحة (`/api/v1/entries/open_events/`).
   - إضافة منطق (Signal أو في دالة الحفظ) لحساب الـ Duration بالـ `ساعة` وإضافة الـ Metric تلقائياً بمجرد ربط إدخال جديد (Child) بإدخال مفتوح (Parent).
   - تحديث الـ Frontend ليعرض الأحداث المفتوحة، ويكتشف الكلمات المفتاحية ليقترح الإغلاق بربط الـ `parent_id`.

**هل توافق على هذا التحليل والنهج؟ إذا كانت الإجابة نعم، سأبدأ فوراً في التنفيذ.**
